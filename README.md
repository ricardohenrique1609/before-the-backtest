**Pre-Freeze Common-Support Ceilings for Event-Driven Strategy Research**

## What this is

A working paper and its complete evidence trail. The paper asks one question: **can an event-study
design be shown to lack adequate common support before any outcome is opened?** It describes a
procedure that answers it, applies the procedure to a real study, and reports that the study was
stopped before its pre-registration was frozen because the comparison it required did not exist.

The scientific content was reviewed over four versions by a deliberately hostile referee and
accepted at version 4. Everything after that is production work, itemised in `CHANGELOG.md`.

## The central contribution

**A pre-freeze common-support ceiling.** Given a proposed event set, a complete point-in-time
candidate-control universe, an intended matching rule, a minimum support per event *m* and a minimum
admissible confirmatory sample *N_min*:

1. construct the candidate-control universe at each event time from information available then;
2. apply the intended matching rule exactly;
3. compute the attainable support `S_e` over the **complete** eligible pool;
4. form `N* = Σ 1[S_e ≥ m]`;
5. if `N* < N_min`, **stop before the pre-registration is frozen and before any outcome is opened**.

The status on stopping is `DESIGN INFEASIBLE UNDER THIS SPECIFICATION` — not a null result, not a
rejected hypothesis, not evidence that the effect is absent. The hypothesis is untested.

**What is inherited and not claimed.** The design-stage principle is Rubin's (2008): observational
studies must be designed without examining outcome data, and a candidate dataset may have to be
rejected for lack of overlap. Outcome-free two-stage design is codified elsewhere; design-stage
overlap diagnostics exist as tooling; positivity and its remedies are established. The paper claims
only the combination — complete population, point-in-time, pre-freeze, outcome-blind, with a
pre-registered numeric stop rule, in a systematic event-study setting — and states that if that
combination has been formalised elsewhere, the contribution reduces to the empirical demonstration.

## How to reproduce

With the pinned environment in `requirements.txt` (Python 3.12.14). Scripts live in
`release/scripts/` in the public package, and in `scripts/` in the research repository.

```bash
python -I scripts/paper_audit_v4.py    # verify every frozen hash, then audit the accepted V4
python -I scripts/release_build.py     # Figure 4 + paper.tex for this package
python -I scripts/release_audit.py     # frozen quantities, claims, cross-references, LaTeX, BibTeX, manifest
```

**What regenerates what.** `release_build.py` regenerates **Figure 4 and `paper.tex`**. Figures 1-3
and all nine tables are carried **byte-identically** from the frozen V4 build and are regenerated by
`paper_build_v4.py`; `BUILD.md` §2 says which command produces which file. No script in this package
recomputes an economic quantity.

The PDF is built with Tectonic; `BUILD.md` §4 records the version, command and output hash.

### Retrieval scripts and the contact address

`scripts/h19_2_prefreeze.py` and `scripts/h19_1_feasibility.py` retrieve from public sources. Fair-
access policies at SEC EDGAR and at the venue archives require an automated client to identify itself

without it:

```bash
export QIE_CONTACT_EMAIL="you@example.org"     # your own address; there is no default
```

There is deliberately no fallback: a placeholder address would be a false identification. **If you
re-use these scripts, supply your own contact address.** No API key or credential is needed for any
retrieval in this project.

Two reproduction paths exist and must not be confused. **Paper regeneration** from the committed
artefacts is deterministic and is what the commands above do. **Raw reconstruction** from public
sources is not deterministic, because the sources are live and mutable; `DATA_RELEASE_POLICY.md`
explains why and what is included instead.

## Important limitations

Stated here because a reader should meet them before the paper, not after it.

- **One demonstration.** The procedure is applied once, to one specification, which returned
  infeasible. The paper provides evidence that the gate can **detect** one infeasible design. It does
  **not** estimate specificity, false-positive rate, or how often the gate would correctly let a
  sound study proceed. No case is reported in which the audit returned feasible and the resulting
  design was later shown to be well identified.
- **The matching rule is the largest unmeasured sensitivity.** The floor *m* and the minimum *N_min*
  are bounded by an arithmetic argument on committed quantities; the matching rule is not. A coarser
  stratification could produce a different ceiling. The paper therefore establishes `DESIGN
  INFEASIBLE UNDER THIS SPECIFICATION`, **not** that the question cannot be identified.
- **No independent replication.** One researcher, one codebase, one venue. Two-pass gold sets measure
  consistency, not independent accuracy. The cheapest viable external check is named in the paper and
  has **not** been performed.
- **No profitability claim anywhere.** No return, carry, P&L or Sharpe ratio is computed in this
  paper for any event.

## Research registry

The paper reports the full denominator rather than only its case studies: 31 registry entries, of
which **9** were rejected on a completed economic test and **1** was promoted — and that single
promotion was later archived for falling below a revised return hurdle. The paper states plainly
that this denominator does not support a broad thesis about quantitative research, and that its claim
is about a procedure, not a prevalence. The detailed cases were selected retrospectively, which the
paper discloses.
